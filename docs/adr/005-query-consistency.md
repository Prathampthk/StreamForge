# ADR 005: bounded queries and truthful snapshot health (accepted Phase 4)

Read only revenue_1m_canonical/traffic_1m_canonical for final analytics. Require a bearer key mapped to one tenant (separate QUERY_API_KEY, defaults provided only in local Compose). Validate unknown/repeated parameters, require tenant_id/from/to/interval=1m and currency for revenue, and reject unaligned minutes or windows >24h. RFC3339 offsets normalize to UTC. Use [from,to) windows and dense zero buckets so empty minutes are explicit. Revenue is a decimal integer string, preserving Int128 without JSON/JavaScript rounding. Never sum currencies into a shared amount. Error rate is API >=500 / API events, or zero with no API events.

Typed ClickHouse HTTP parameters separate values from SQL. SQL identifiers come from fixed endpoint constants only. Bound concurrent HTTP work, database connections, server query time/memory/threads, response bytes, response row count and shutdown. Query readiness requires both canonical refreshes healthy. Each metric request checks its own refresh immediately before reading, fails on missing/failed/disabled/too-old snapshots, and rechecks the conservative observed age after reading. Return the *earlier observed* successful refresh time as a lower bound, never label a later metadata read as the snapshot that supplied an earlier query. These targets atomically replace independently; no cross-endpoint transaction is promised. Refresh time is not a Kafka processed watermark and does not establish event freshness.

Observability is optional local infrastructure: Prometheus with DNS discovery for consumer replicas, provisioned Grafana metrics/Jaeger datasources and pipeline dashboard, OTel Collector -> Jaeger in-memory trace storage. No frontend or application-dashboard project. All published ports bind loopback. Bounded queues/sampling and finite metric labels are required. Query/ClickHouse spans use fixed operation names, without raw SQL values, event/tenant labels or credentials.

Reconciliation consumes an explicit bounded manifest of accepted logical events (with per-delivery acknowledgment timestamp optional), compares exact canonical payload/IDs, verifies conflict quarantine, computes expected UTC-minute business metrics independently, and compares the canonical snapshots only in manifest-owned buckets/tenants. It reports missing/extra/conflicted IDs, raw duplicate evidence and exact per-currency sums, and exits nonzero on mismatch. Unknown/unacknowledged submissions must never enter an accepted manifest. Empty tenants/windows can be checked explicitly; a manifest is not a load generator. A dry reconciliation cannot claim broker-failure durability or SLO attainment.

Tradeoffs: dense 1440-row responses simplify callers but require aligned minute boundaries; versioned pagination is unnecessary for this bounded window. Global refresh failure denies queries for all tenants conservatively. Read-time metadata costs extra database work; a health cache could hide failures and is deferred pending measurements. A one-second refresh schedule and one smoke timing are not latency/freshness benchmarks. Full-state refresh/storage costs from ADR 003 remain unresolved scaling risks.
