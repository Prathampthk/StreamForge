# ADR 006: durable quarantine, bounded operator replay (Phase 5)

Only structural/domain poison is quarantined. Transient ClickHouse failures remain retry/backlog. Process valid partition prefixes before poison, then publish the complete bounded raw envelope to acks=all Kafka, record its durable acknowledgment in PostgreSQL, and only then allow the next source offset. Any DLQ/audit error leaves the failed record and all later delivered offsets uncommitted. PostgreSQL is touched only for poison/replay, never every valid event.

A compact audit row uniquely identifies source topic/partition/offset and a deterministic envelope UUID. A row lock serializes competing quarantine attempts; a confirmed published row avoids normal repeated publication. Kafka acknowledgment and PostgreSQL are not an atomic transaction: a crash after Kafka ack/before audit commit may emit a duplicate envelope. Stable IDs expose this at-least-once boundary; do not claim transactional exactly-once DLQ. Canonical source topic deletion/recreation/offset resets are outside this coordinate identity model. Source topics are immutable in normal operation.

Original bytes/key are base64 encoded. Only the four documented safe Kafka headers are retained; arbitrary headers (e.g. Authorization) are deliberately omitted to avoid copying credentials. The raw poison body itself is forensic opaque data and requires restricted access; no payload/envelope is logged. Errors are fixed sanitized codes. DLQ topic max bytes rises to 2MiB to accommodate base64 of a <=1MiB source record; no truncation. Seven-day DLQ retention is explicit, compact audit outlives it.

Replay is an OS/operator-controlled CLI (no public unrestricted endpoint), dry-run by default, one DLQ partition and finite [from,to) range, <=1000 offsets and <=16MiB planned data, explicit tenant and actor. Prevalidate the entire selection before publishing anything. Invalid payloads require an explicit repair map; original parseable event ID must be preserved and tenant/key must match. Malformed envelopes or identity-changing repairs are rejected. Dry-runs write audit metadata but never Kafka. Actual replays preserve logical identity and use acks=all. Job IDs/selectors are immutable; a PostgreSQL advisory lock excludes concurrent execution. Resume skips acknowledged audited records; ambiguous publish-before-audit gaps can repeat the same logical ID safely. Same-ID changed payloads remain quarantined by canonical analytics, not silently overwritten.

No Kafka transaction spanning PostgreSQL/ClickHouse is claimed. Transactional DLQ+source offset commits would narrow the Kafka boundary but complicate the existing sink-first epoch model and still not atomically cover external audit state. Explicit at-least-once envelopes plus canonical replay are simpler to test. CLI credentials are local development metadata/broker access; production authentication/TLS/IAM is Phase 6.
