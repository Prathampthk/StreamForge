# ADR 008: private, approval-gated AWS development deployment

Phase 6 prepares a single-region dev environment, not a production HA claim. Use private ECS Fargate applications, private EC2 Kafka/PostgreSQL and ClickHouse, encrypted retained data volumes, SSM access, regional VPC endpoints and no default NAT gateway. A public ALB is optional and requires an existing ACM certificate plus explicit allowed client CIDRs. API keys remain single-tenant bearer keys supplied through per-service Secrets Manager entries; production tenant key rotation/authentication is not claimed.

Use TLS with hostname verification for Kafka, ClickHouse and PostgreSQL; Kafka clients additionally use SCRAM-SHA-512 and topic/group ACLs. No insecure-skip-verification escape hatch. Public HTTPS terminates at the optional ALB; its private target hop is HTTP and is restricted by security groups. Secret values and certificate private keys never enter Terraform variables, user-data or Git. Runtime instance/task roles read only their own secret ARNs. Separate execution and application task roles. Private ECR images are immutable SHA256 digests; GitHub publishing uses a repository/environment-bound OIDC role, not stored AWS keys.

Bootstrap infrastructure first with application services disabled, populate secrets and mirrored images, then review a second plan before enabling services. Stateful bootstrap must fail visibly rather than formatting an existing filesystem or overwriting initialized state. EBS data and secrets have deletion protection/retention guards; teardown requires explicit review. An S3 backend uses encryption, versioning and lockfiles after a separately approved bootstrap; local state is never committed.

Alternatives: managed MSK/RDS and NAT simplify some operations but increase recurring dev costs; RDS remains optional and is not created. Kubernetes is outside scope. Multi-broker replication and ClickHouse HA are not represented by the cheaper single-node profile. Phase 5's growing canonical refresh failure remains a deployment blocker for a usable analytics demo; cloud resources do not establish fresh-query or end-to-end throughput guarantees.

All cloud creation, apply, image publication and deletion await separate spend/action approval. Local format/validate, mock-provider plan tests, container checks and security scans are authorized now. Live AWS plan/smoke/load/restart/cleanup evidence must be marked unverified until an account and temporary environment are approved.
