# AWS development deployment — prepared offline

**No AWS environment has been deployed.** The user chose offline preparation. Commands below are a reviewed procedure for later use, not executed evidence. An authenticated plan, its spend, any publication/apply and any deletion require separate approval. The current Phase 5 full-history refresh bottleneck remains unresolved; this dev topology does not establish a usable large-history analytics demo.

## Topology and prerequisites

Commercial AWS, default `us-east-2`; one availability zone hosts ECS tasks, Kafka/PostgreSQL and ClickHouse. Two private subnets are defined; the second supports a later reviewed topology change. Six interface endpoints (ECR API/DKR, logs, secrets, SSM, SSM messages) occupy the first AZ; S3 uses a gateway endpoint. No NAT, public data-node IP, SSH ingress or public database listener is provisioned. Optional ALB/public DNS needs an existing regional ACM certificate, Route53 public zone, hostname and explicit client CIDRs. Only HTTPS 443 forwards the two public API paths; health/metrics/replay endpoints are not public routes. The ALB-to-task hop is private HTTP.

Two x86_64 hosts: t3.medium for Kafka+PostgreSQL, r6i.large for ClickHouse. Choose a reviewed AMI containing Docker, AWS CLI v2, Python3, xfs tools and current SSM Agent (an appropriately reviewed ECS-optimized AL2023 image is a candidate). Bootstrap fails if prerequisites are missing; it has no Internet package-install fallback. Each host has an encrypted 20GiB root disk and retained, encrypted 100GiB gp3 data disk. Kafka T3 credits use `standard` to avoid unlimited-credit billing; exhausted credits can reduce throughput. This is single-node, non-HA dev infrastructure. Optional RDS is not created.

Use Terraform 1.17.1, AWS provider 6.72.0, AWS CLI v2, Session Manager plugin and an authenticated named profile. The ordinary `scripts/terraform.sh` deliberately mounts **no AWS credentials**. Account ID, region, AZs, AMI, existing GitHub OIDC provider (if any), domain/certificate and image digests must be selected before a live plan. Never paste secret keys into chat or Git.

## Review stages

1. **Offline checks:** `make cloud-check` validates schemas/mock plans, certificates/rendering and workflows. `make security` checks the Go call graph. CI also builds/scans app images. Mock plans do not contact AWS or prove service availability/IAM authorization.
2. **State bootstrap plan:** `infra/terraform/bootstrap` prepares a versioned, private, customer-KMS-encrypted S3 state bucket and retained KMS key. Initialize and plan with the approved named profile/account. Save the plan privately. Do not apply until its actual account/resource changes and costs are approved. The bootstrap's local state contains infrastructure metadata and must be retained privately, never committed.
3. **Remote backend:** after separately approved creation, convert the bootstrap `backend_config` output into `.aws-artifacts/backend.hcl` (HCL key/value literals). Copy `envs/dev/backend.tf.example` to ignored `envs/dev/backend.tf`. Backend settings include encryption, the KMS ARN, versioning, `use_lockfile=true`, account allow-list and key `streamforge/dev.tfstate`. Restrict state access to deployment operators; the GitHub image publisher has no state access.
4. **Base plan:** copy `deployment.tfvars.json.example` to `.aws-artifacts/deployment.tfvars.json`; replace the example account and `release_id`. `release_id` identifies the reviewed **stateful bootstrap/schema bundle**. Keep it fixed for app-only releases. Initially leave `enable_stateful`, `enable_apps`, `public_access` and `enable_publisher_role` false. Export AWS_PROFILE/AWS_ACCOUNT_ID/AWS_REGION and run `scripts/aws/plan.sh`. It checks the caller account and a clean reviewed checkout, initializes the selected backend and writes a private saved plan. It never applies. Review and separately approve the saved plan before an operator applies it.
5. **Secrets:** create fresh offline material with `python3 scripts/aws/prepare-secrets.py --name streamforge-dev --out .secrets/aws-dev`. It refuses overwrite, uses private file modes and issues separate broker/metadata/ClickHouse leaves. Leaves expire in 30 days; retain the CA key offline. After approved base creation, save Terraform outputs privately. Only after explicit upload approval, use `upload-secrets.py --confirm 'Upload reviewed secrets' --directory .secrets/aws-dev --outputs .aws-artifacts/outputs.json`. It writes existing account-checked secret ARNs; no values are printed or placed in process arguments. Root/server credentials are separated from app credentials. No secret versions are Terraform-managed.
6. **Images:** public vendor source images are digest-pinned in `deploy/vendor-images.json`; Go images use a digest-pinned patched build toolchain. Use the separately approved publisher procedure. Select a docker-container Buildx builder using the pinned BuildKit image from the workflow; the manual workflow configures it automatically. `publish-images.py --confirm 'Publish reviewed images'` validates account/region/project, builds linux/amd64 images and scans **all seven images before the first push**. Vendor scan success has not been claimed locally; any finding blocks publication. Capture `.aws-artifacts/images.json`, merge its map into the deployment variable file, and keep every image reference as an immutable private ECR digest. Do not replace a failed scan with a mutable tag or blanket waiver.
7. **Stateful plan:** set `enable_stateful=true`, provide the reviewed AMI and all image digests. Review a new authenticated plan/cost before approval. Bootstrap waits for the expected EBS serial, rejects root/unknown filesystems and formats only an empty new volume. Ownership/schema markers protect retained data. Secret retrieval uses scoped roles. Initial schema applies only to an unmarked project disk; changed schema content requires an explicit migration. Wait for cloud-init completion and inspect sanitized logs; Terraform instance creation alone does not prove bootstrap succeeded. Allow up to 20 minutes for volume/readiness waits before investigating.
8. **Application plan:** once verified schema/auth/TLS endpoints are ready, set `enable_apps=true`. Review/approve the new plan. ECS tasks use non-root read-only root filesystems, dropped capabilities, private ENIs, bounded resources, 120-second stop grace and circuit-breaker rollback. Three services start; replay is a separate operator task definition, never a public API. Default app roles have no AWS API policy. The three incremental views explicitly execute as their trusted definer, so consumer INSERT does not require raw-data SELECT; only administrators may change those definitions. Execution roles pull only their own images, read their own secret and write their own log stream. Cloud Map exposes private app DNS under `apps.streamforge-dev.internal`.
9. **Optional HTTPS:** only after approving the private demo, set public inputs. The separate ALB log bucket uses S3's SSE-S3 encryption because ALB access logs do not support SSE-KMS. Artifact/state buckets use customer KMS keys. ALB deletion protection and retained bucket/data guards are intentional. Never open client CIDRs to `0.0.0.0/0` or route metrics/admin endpoints publicly.

Applying an infrastructure plan, updating service flags, uploading secrets and publishing images are distinct external actions; none was authorized/executed by the offline checks. There is no automatic apply/deploy/destroy workflow.

## GitHub publication setup (optional)

CI requires no cloud credentials and runs on PRs/main pushes. The release workflow is manual, main-only, requires a confirmation phrase and environment `aws-dev-publish`. Before opting into its IAM role, restrict the environment to main (or protected branches with main protected). The workflow verifies branch restrictions through a read-only API call **before** assuming AWS credentials. Additional reviewers are optional; a sole owner can deliberately dispatch an approved publication without needing a second person. The IAM OIDC subject binds the exact repository/environment and audience. Existing OIDC provider ARN can be supplied to avoid account-wide provider ownership conflicts. `enable_publisher_role` is false by default.

Set environment variables AWS_ACCOUNT_ID, AWS_REGION, ECR_PREFIX and AWS_PUBLISH_ROLE_ARN only after the actual plan/permissions are approved. The role permits scoped ECR publication only, not secrets access, IAM mutation or Terraform/ECS/EC2 deployment. A rerun at an already published immutable Git tag may be refused; inspect and reuse the verified digest instead of deleting/replacing it.

## Live checks still required

Use SSM to forward private API ports through the operator host; e.g. AWS-StartPortForwardingSessionToRemoteHost targeting `ingest-api.apps.streamforge-dev.internal:8080` and local 18080, and query port 8082 to local 18082. The host's operator SG permits only the necessary private API/database/broker connections. Session access itself needs an approved operator IAM policy. Keep keys in private files/environment; do not put them in command-line JSON or CloudTrail command parameters.

Before a live demo: verify ingest/query readiness, wrong-key/tenant rejection, verified TLS and wrong-CA rejection, negative Kafka topic/group ACLs, denied query INSERT/ALTER/raw reads, denied consumer DDL, denied cross-service secret access, persistence across host restart/redeploy, DLQ unavailable behavior, replay dry-run and exact golden reconciliation. Record actual instance/task sizes and image digests. Do not call a healthy container a healthy analytics pipeline.

A cloud performance test additionally needs an approved load host, duration, artifact export path and spend budget. Use the existing deterministic driver/receipt audit, two query windows and unique probe scheme; do not extrapolate the Mac's 10,335 acknowledgment/s to AWS. The load runner should be separate from Kafka/ClickHouse, and all receipts must be retained privately for exhaustive ID/metric reconciliation. No AWS throughput, freshness, restart or cleanup result is currently verified.

## Migration and rotation

Take and verify a retained-data backup before schema/major-version changes. Changed bootstrap/schema hashes fail visibly; they do not auto-upgrade existing state. Do not change `release_id` or stateful image digests for an app-only release. The node template includes only its stateful images, so app digests do not force node replacement. Stateful replacement reuses the expected EBS data volume and is an outage, not rolling HA.

Changing a secret does not rotate the database/broker identity or running task environment automatically. Coordinate server credential/ACL changes, secret versions, certificate trust overlap and a reviewed task redeploy; verify rejection of the old credential before retiring it. Replacing CA material without a coordinated transition can stop the pipeline. Expiry, retention/backups and incident response remain operator duties. Use the [teardown procedure](teardown.md) for stopping/retaining/removing resources.
