# Stop, retain and teardown review

No AWS resources have been created or deleted in this offline phase. This is a future operator procedure. Never run an unreviewed destroy/apply, remove deletion guards automatically, or treat a failed command as cleanup proof.

1. Capture the approved account/region, Terraform state/resources, task/image digests, accepted manifests, backup snapshots, restore checks and retention decisions. Save artifacts privately. Confirm ownership tags; shared OIDC providers, zones, certificates and state buckets require special ownership review.
2. To stop new traffic, restrict public entry and drain/scale ingestion/query/consumers in a separately approved change. Preserve source offsets and Kafka retention; reconcile the final acknowledged cohort. Stop a benchmark runner first. Stopping stateful hosts without draining can require replay; it is not a loss proof.
3. An approved pause can set ECS service counts to zero and stop the two EC2 instances. Do not set `enable_stateful=false` to bypass retained-volume guards. Review the continued charges for VPC endpoints, root/data EBS, secrets/KMS, DNS/logs and storage; see costs.md.
4. Before deletion, request separate approval for the exact inventory and specify which data/backup/secret/state objects must remain. EBS data volumes, secrets, artifact/state buckets, KMS keys and newly owned OIDC providers have `prevent_destroy`; ALB has deletion protection. A destroy plan can correctly fail on these guards. That is not a cleanup failure to bypass silently.
5. Only after explicit approval and verified backups, make a focused reviewed change removing the guards for **owned, selected** resources. Prepare a private saved destroy plan and inspect every delete/replace. Apply only the approved plan. Bucket `force_destroy=false` refuses nonempty buckets; do not bulk-empty them or delete versioned state/history without specific approval. Secrets use a 30-day recovery window; KMS keys use delayed deletion. Never delete shared certificates/OIDC providers by assumption.
6. Verify with read-only AWS queries: ECS service/task counts, running/stopped EC2, unattached retained volumes/snapshots, ENIs/endpoints/ALBs/public addresses, ECR/S3 object storage, secrets pending deletion, KMS pending deletion, DNS, log groups and remaining IAM roles. Compare to the approved retained-resource list and check billing later for delayed usage. Terraform output alone does not prove zero remaining spend.
7. Remove remote-state/bootstrap resources last, after all other state is securely archived. Retain the bootstrap local state until its own approved teardown is complete. No cleanup verification is claimed until actual AWS reads and inventory evidence have been recorded.
